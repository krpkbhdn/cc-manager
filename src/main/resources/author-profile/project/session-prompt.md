## Project setup (applies to `{{projectPath}}`)

First examine the project: languages and frameworks, build files, whether it is a git repository, and whether `CLAUDE.md`, `.gitignore`, `.jscpd.json` and a `graphify-out/` folder already exist.

1. Project CLAUDE.md: read `{{projectPath}}/CLAUDE.md` (it may not exist). The rules to apply are in `{{profileDir}}/project/claude-md-rules.md`. Adapt them to this project: drop or reword anything that does not fit its language or tooling (for example the version file or test conventions), keep the intent. If CLAUDE.md is missing, create it with the adapted rules. If it exists, propose only the missing sections or lines (skip those already covered) and wait for the go-ahead before editing.
2. graphify: make sure the `graphify` CLI works (`graphify --version`); if not, install it with `pip install graphifyy` (or `uv tool install graphifyy` / `pipx install graphifyy`) and run `graphify install`. If the project is a git repository, run `graphify hook install`; if it is not a git repository, skip the hook. Make sure `graphify-out/` is in `.gitignore` (create or append the line; propose the edit first when `.gitignore` already exists). Building the initial graph is optional and costs tokens, so ask the user before running `/graphify`. `graphify update .` is AST-only and free, run it whenever a graph already exists.
3. jscpd: make sure `jscpd` is available (`jscpd --version`; if missing, `npm i -g jscpd` when npm exists). Use `{{profileDir}}/project/jscpd.json` as the template for `{{projectPath}}/.jscpd.json` and set `format` to the languages actually present in the project (jscpd format names such as java, kotlin, typescript, python). If `.jscpd.json` exists, propose a merge instead of replacing it. Add `jscpd-report/` to `.gitignore` as well.
4. Do not build, test or commit anything as part of this setup.
