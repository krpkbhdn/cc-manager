## Screens
Claude Code Manager runs and manages many local Claude Code sessions. Everything runs on this machine against your own Claude Code installation. Routes: Overview, Sessions (Active and History tabs), Assistant, Prompt Library, Teams, Usage, one screen per project or group, and the extension pages Plugins, MCP servers and Skills. The Usage screen (opened from the "Open usage history" button of the usage panel in the top bar, Ctrl+Shift+Y, or the palette entry "Show usage history") shows daily spend charts by project and model, top sessions and a period summary; thresholds for the 5h/7d limit and the daily budget are set in Settings > Usage. The top bar has the usage chip (limits, context, cost; Ctrl+Shift+Y) and notifications (Ctrl+Shift+M); the status bar shows usage meters. Dialogs close with Esc.

## Sidebar
Without a heading: Overview (Alt+0), Sessions (Active and History tabs) and Assistant, with badges (live sessions, sessions waiting for you). Then the Library section (Teams, Prompt Library), the Extensions section (Plugins, MCP servers, Skills) and the Projects tree: projects and groups, with "Add project" and "New group" at the end. Projects 1 to 9 open with Alt+1 to Alt+9. Sections fold and unfold, and the sidebar remembers which are folded and whether it is collapsed. When collapsed to the icon rail, Library, Extensions and Projects open as drop-down menus. The search field opens the command palette. Collapse or expand with Ctrl+Shift+B.

## Sessions
A session is one Claude Code run in a terminal drawn inside the app. A project screen has tabs: session tabs, shell tabs, Git, Run and Activity. Launch Claude starts a new session; Continue last session and Resume a session reopen earlier ones; Start task with team starts the team's lead with a task. Session status: green idle, yellow working, red needs action, grey offline. When Claude asks something (a question, plan approval, tool permission, MCP form) a dialog opens in the app; Answer in terminal hands it back to the terminal, and Esc only hides it (the Answer button or the attention card reopens it). Ctrl+Shift+N answers the next waiting session. The model control in the tab strip shows the live model and effort and switches them. The agents rail (Ctrl+Shift+J) lists subagents. The Sessions screen (Ctrl+Shift+S; its History tab searches past conversations, Ctrl+Shift+F) shows every session with project, status, last action, context and cost, with status and project filters and an optional by-project grouping. Shell tabs are plain terminals in the project directory (Alt+F12).

## Groups
A group bundles several projects into one workspace (sidebar "New group" or palette "New group"). A group session runs in a workspace folder and sees every member through --add-dir, including their CLAUDE.md. The group screen has a Members tab instead of Git and no Run tab; "Edit group" changes the members. Groups appear in the sidebar tree and can be used in the Sessions grouping. The Assistant creates a group or replaces its members with set_group (id to update, name, members as project ids); deleting a group is done in the app. start_session and resume_session accept a group id too.

## Teams
Teams (sidebar) are sets of agent roles. Each non-lead role becomes a native subagent with its own model, effort and tool allowlist; the lead role starts the session with the team's instructions and the task as first prompt. Create or edit a role in the role dialog; every change is saved at once. A project can have a default team that every launch from the UI uses. "Start task with team" asks for the task text. The Assistant uses list_teams, set_team (creates, or with id replaces the whole role list; exactly one lead) and delete_team (both ask permission, since role prompts and tool allowlists run in later sessions).

## Prompts
The Prompt Library (sidebar) keeps reusable prompt templates, optionally bound to a project or default team. Placeholders {project}, {branch} and {file} are filled when the template is used; unknown ones stay as typed. Pick a template from the session tab strip or the queue. The Assistant uses list_prompts, get_prompt, set_prompt (create or update by id, asks permission) and delete_prompt (asks permission).

## Queue
Each session has a prompt queue (button in the tab strip with a count). A queued prompt is typed once the session is idle, then one per finished turn. The queue waits while the session needs your action, after you interrupt with Esc, while you have an unsent draft in the terminal, and right after a send until the next turn starts.

## Runs
Run configurations (name, command, directory) are per project. Run, Restart and Stop are in the project header; the Run tab shows status and the console. Ctrl+Shift+R runs the selected configuration. Claude can register a configuration for its own worktree through the bundled run-configurations skill.

## Git
The Git tab (Ctrl+Shift+G) has Changes (file lists, hunk diff, commit box; Ctrl+Shift+D, commit Ctrl+Shift+K), Log (graph and details), Branches (Ctrl+Shift+H switches branch), Worktrees, stashes and tags. Fetch, pull, push (Ctrl+Shift+U), checkout, new branch, stash and create worktree are also palette entries "Git: ...". Operations run off the UI thread, one at a time; errors show with a suggested action.

## Extensions (skills, plugins, MCP)
Plugins (marketplaces, installed plugins, install and update), MCP servers (list with health, add, remove, sign in) and Skills (list, view, create) each have a page in the sidebar. Entries have a scope: user (all projects), project (shared in the repository) or local (private to one project). Project settings (Ctrl+Shift+comma) shows the project's plugins, MCP servers and skills. MCP servers a project declares in .mcp.json need your approval. Claude loads new extensions when a session starts. The Assistant uses list_skills, get_skill, set_skill and delete_skill (user or project skills; plugin skills are read-only); list_plugins, get_plugin, install_plugin, uninstall_plugin, set_plugin_enabled, add_marketplace and remove_marketplace; list_mcp_servers, get_mcp_server, add_mcp_server and remove_mcp_server. Skill and plugin tools take optional project and scope (default: project scope when a project is given, else user); a project id also works for a group. MCP server output hides env, headers and the URL credentials, path and query (only host and port remain; a command shows its executable only), and marketplace references are masked the same way. check_mcp_health shows connection status and always asks permission because `claude mcp list` can start servers. MCP server tools default to local scope when a project is given (private to you), else user. install_plugin never confirms a plugin that runs a command: it reports it and you confirm in the Plugins page. set_team, set_skill, delete_skill, install_plugin, uninstall_plugin, set_plugin_enabled, add_marketplace, remove_marketplace, add_mcp_server and remove_mcp_server ask for permission; list_ and get_ tools do not.

## Presets
Project presets (Settings, Project presets) are named sets of components applied to a project folder: marketplaces, plugins, skills, agents, MCP servers, CLAUDE.md instructions, a settings fragment and files. The Assistant reads them with list_presets, get_preset (preset_id; with component_id the whole text of one instruction, skill or agent; MCP configs and settings are redacted to keys; FILE shows path and size only; instruction/skill/agent text is shown) and plan_preset (project_id, preset_id: what applying would do, writes nothing). It edits them with create_preset, update_preset, duplicate_preset, delete_preset, restore_preset, add_preset_component (kind, name and the fields of the kind; a plugin also adds its marketplace when known), update_preset_component, remove_preset_component and move_preset_component, and writes into a project with apply_preset (project_id, preset_id, optional component_ids). All of those ask permission; list_presets, get_preset and plan_preset do not.

## Review
The Review tab (Ctrl+Shift+Z) shows screenshots an agent submitted with the visual-review skill. Tools: Pointer (default; selects, moves and resizes marks by 8 handles), Rectangle, Ellipse, Pin, Freeform (click to place each vertex, click the first point or press Enter to close the polygon, Backspace removes the last point, Esc or a right click cancels; hover an edge and press to add a draggable vertex). Right-click the image to draw ONE element (R rectangle, E ellipse, P pin, F freeform), then the default tool is back; Esc or V cancels. Delete/Backspace removes the selected mark (not while typing a comment). Hold Ctrl (Cmd on macOS) and drag the left mouse button, or drag with the middle button, to pan, wheel zooms. Marks are numbered with a comment; then Send to agent (a bound or chosen session, or a new one) or Approve to settle the review. The first submit asks permission.

## Shortcuts
Ctrl on Windows and Linux, Cmd on macOS where noted; chords use Ctrl+Shift so plain Ctrl+letter reaches the terminal. Ctrl+Shift+P or Ctrl+K command palette; Ctrl+Shift+O or Ctrl+N add project; Ctrl+Shift+T new Claude session; Ctrl+Shift+S sessions; Ctrl+Shift+F search session history; Ctrl+Shift+I Assistant; Ctrl+Shift+E ask the Assistant; Ctrl+Shift+N answer next waiting session; Alt+F12 open terminal; Ctrl+Shift+W close session tab; Ctrl+Tab and Ctrl+Shift+Tab next and previous tab; Ctrl+Shift+B sidebar; Ctrl+Shift+J agents rail; Ctrl+Shift+Q quick actions; Ctrl+Shift+L theme; Alt+0 overview; Alt+1..9 project; Ctrl+Shift+G Git tab; Ctrl+Shift+R run; Ctrl+Shift+Z review tab (screenshots Claude submitted, marked up and sent back); Alt+F11 web review tab (mark elements of a running web page, edit their styles, check spacing, pick similar elements, try device sizes, right-click for feedback on a layer, send to an agent); on the web canvas plain keys work (I pick an element, Shift+I keeps picking, Q quick feedback, S screenshot of the visible part to the Review tab (screenshots join one pinned review chosen in the toolbar; when it is full or sent you are asked for a new one; the Review tab never opens by itself), Shift+S whole page, R region, O overlays, 1-5 overlay groups, L lock page, T rotate, 0 and Shift+0 zoom, +/- zoom; off while typing in the page, Esc backs out); Ctrl+Shift+A activity tab; Ctrl+Shift+M notifications; Ctrl+Shift+Y usage; Ctrl+Shift+X context usage of the selected session (what fills the context window, measured by `claude /context all` with a plain `/context` fallback; rounded and ~ values are approximate; the status bar offers /compact when it passes 70%); Ctrl+Shift+comma project settings; Ctrl+Shift+. app settings; Ctrl+Shift+backtick focus terminal; F1 or Ctrl+Shift+/ keyboard shortcut sheet. On macOS most chords use Cmd instead of Ctrl+Shift; the shortcut sheet shows the exact ones.

## Command palette
Ctrl+Shift+P (or Ctrl+K) opens a search over sessions (jump to one), projects and groups (open), and actions: add project, new group, navigation to every screen, launch/continue/resume, start task, open terminal, open folder, open in IDE, add IDE, project settings, run/stop, Git entries, switch model, notifications, usage, theme, sound, sidebar, Assistant help and Assistant at startup. Actions for the project on screen are listed only while that project is open.

## Assistant
The Assistant is a Claude session outside any project, started from the sidebar, Ctrl+Shift+I, or at startup (ask, start automatically, or never; cycle it with the palette entry "Assistant at startup"). It controls the app through the cc-manager-app tools: list, add, open and remove projects (list_projects, get_project, add_project, open_project, remove_project); start and resume sessions, queue prompts (start_session, resume_session, list_sessions, queue_prompt); start and stop runs (list_runs, start_run, stop_run); git (git_status, git_branches, git_worktrees, git_log, git_diff, git_fetch auto; git_checkout, git_commit, git_pull, git_push, git_add_worktree, git_remove_worktree ask); navigate to overview, sessions, assistant, teams or prompts; groups, teams, prompts, skills, plugins and MCP servers as described in their topics; and get_help for this help. Read-only and easily undone tools (list_, get_, navigate, set_group and similar) run without asking; queue_prompt, set_prompt, add_project, start_run, stop_run, start_session, resume_session, removing or deleting things, set_team, git writes, skills, plugins, marketplaces and MCP servers show a permission dialog in cc-manager; the tool runs only after you allow it there, and Deny or no answer leaves things untouched. Ctrl+Shift+E sends it a one-line request without leaving the current screen. "Assistant help" in the palette lists hotkeys and tools.
